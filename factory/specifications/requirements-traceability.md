# Operator requirements traceability matrix

This live matrix decomposes the [operator source](../sources/operator-brief.md) into stable atomic requirement IDs. Source labels below identify the numbered interview item or named subsequent directive in that source. They distinguish confirmed requirements from the engineering proposals listed separately. Later operator requirements get new IDs; never silently renumber or delete rows.

**Current evidence baseline:** the first document CLI is implemented and undergoing milestone verification. Rows linked to [CLI evidence](../sources/cli-milestone-evidence.md) have bounded implementation coverage; they do not claim full GUI/runtime or release acceptance. Unlinked product rows remain planned. No release exists, so every current-release result remains unfulfilled. Versioning and documentation policies are adopted; automated release enforcement remains pending.

For each row, replace the implementation placeholder with code/test paths and the introducing revision when implemented. Link immutable first-implementation evidence and a **current release** result independently. Per-release Reference records follow [release evidence](release-evidence.md), including test results, versions, verifier, artifacts, video timestamps and approved exceptions. Historical results do not establish a current pass. Optional MCP Apps qualification requires an honest disposition, not guaranteed interoperability or premature CLI removal.
